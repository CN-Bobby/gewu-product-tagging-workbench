# 本地单工作区规则

更新日期：2026-11-03

## 平时怎么做

1. 只在 `D:\数据打标项目` 修改和运行工作台，不在本机维护多份 DEV、TEST、PROD 或 Codex worktree。
2. 改动后就在这个工作区运行、观察和修复；同时只运行一个实例。
3. 用户要求保存改动时，提交到当前 GitHub 分支；用户要求上传时，推送该分支。普通修复不升级应用版本号。
4. 用户明确说打包或发布时，再从指定提交打包并创建/更新对应 GitHub Release。

## 当前保留的边界

- 现有工作台数据、模型/API 凭据、MCP 设置、运行配置和桌面快捷方式仍各自保留；本次流程整理不移动、不重置、不删除它们。
- 选择唯一的日常数据目录前，不把旧 DEV/TEST/PROD 数据自动接到新工作区。空白隔离目录只用于启动验证，不承载真实业务。
- 历史分支、提交和旧工作区先归档留存。只有归档核验完成且清理方式可用后，才移除旧工作区。

## 判断是否完成

- 改动在 D 盘唯一工作区。
- 单实例健康信息指向本次启动的源码和明确的数据目录。
- Git 提交、GitHub 推送、打包、Release 是不同动作；按用户当次要求分别执行并报告。
