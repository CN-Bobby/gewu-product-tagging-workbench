# 商品打标工作台：下一轮改造计划

状态：计划已汇总，尚未实施本轮改造。

依据：用户下午352行泳衣测试的九项反馈、初始表头问题、每批表头不同但内容相近的要求，以及《下午352行测试诊断-20260907.md》。承接持续草稿、明确确认后执行、中文输出、人工修改保护及版本冻结的既定要求。

## 一、用户最终工作方式

上传任意常见表头的商品表 → 查看原始商品及识别出的字段用途 → 后台建立文字底稿与基础数据概览 → 在一个对话入口讨论目标、参考知识、提出标签和执行范围 → 一份提案一次确认 → 表格逐步填入 → 用自然语言圈定异常并局部修正、重试或替换任务 → 继续追加/聚合标签 → 主动保存正式版本。

展示哪些列、执行哪些列、处理哪些商品分别控制。对话能主动查询并圈定范围，用户审核具体影响，无需手动收集内部商品ID。全局画像与知识建议围绕当前目标展开，不自动建立整套标签。

## 二、阶段1：把输入和失败处理修正确

### 1. 每批独立识别字段，不要求统一Excel表头

- 原表头、顺序、原值、数值类型、图片和原行号保持完整；每个输入字段分配数据集内稳定身份，显示名称与内部用途分离。
- 使用表头、字段类型和少量内容样本识别用途。先用明确别名/格式规则，再对不确定部分做模型判断；不能只增加一批硬编码名称。
- 允许标题/商品名称/Product Title等映射同一用途，也允许详细信息＋参数＋规格说明共同提供证据。不把多个来源拼成不可追溯的字段。
- 每批重新验证映射。历史映射作为建议，不能按列位置盲目沿用；列名改变、顺序改变、同名含义改变必须可识别。
- 上传后先显示原表；展示字段识别摘要，仅歧义项要求选择。某用途不确定时，只等待依赖该用途的任务，其他商品浏览和独立任务继续。
- 未匹配列仍在字段目录中，可被对话查询、筛选、读取和指定为标签输入。映射用途不构成字段白名单。
- 保留父ASIN/子ASIN、SKU/内部货号的区别；月份销量和期间累计分别记录时间范围与单位，不能合成无口径的“销量”。
- 固定商品标识区按实际来源显示“ASIN”“父ASIN”“SKU”或“原始行号”，不能用SKU值配ASIN表头。内部商品ID独立于可重复的SKU/父ASIN。
- 网页与AI工具共用字段目录。原字段按原顺序展示，默认包含识别商品所需字段，并按数据集保存列显隐、宽度等偏好。原有件数标签直接可作为条件或输入。
- 现有352行数据从已保存原文补建字段映射，无需重新上传；映射修订仅使依赖它的底稿/结果失效，先展示影响，不自动全量重打。

### 2. 底稿按所需信息使用，错误可定位

- 修复模型顶层/商品项/facts/证据的类型检查。有限接受无歧义的结构变体；其余记录为结构错误并拆分未成功项，避免list.get直接击穿整批。
- 原文证据使用稳定字段ID与位置，显示原表头；兼容可明确还原的字段别名，不能为了通过校验任意改写引文。
- 保存脱敏的请求来源、响应候选、finish_reason、校验路径、错误码与尝试记录。区分网络限流、截断、JSON结构、证据不足、候选不符、规则冲突、上游失败。
- 底稿按属性/来源保留可用事实与失败原因。只依赖SKU尺码的任务，不被无关颜色或护理信息提取失败阻断。
- 明确可直接按原文规则解析的任务允许使用原文；需要缺失证据的任务等待或提出补充提取，不静默跳过所需证据。
- 增加受控的字符串提取、分隔、正则、单位/数值转换、区间映射能力；已确认的Size取上界规则由程序处理，无需逐行模型推断。变体尺码列表和歧义单独标记，不擅自压成一个值。
- 继续/重启只处理当前有效的未完成项；请求和时间同时保留每次尝试及累计指标。

### 3. 任务所有权与失败收尾

- 单元格写入绑定任务代次、规则修订和人工编辑版本；成功、失败、取消和重试路径均验证，防止旧任务把新成功结果写成失败。
- 对重叠执行范围检测并提示冲突；同一请求重复提交具有幂等保护。
- 区分执行历史与待处理问题。任务可暂停、取消、局部重试、作废/归档、被后续任务替代；历史证据保留但不无限进入待办。
- 从失败详情直接进入：按错误类型圈行、查看原文/拒绝候选、修改规则、换范围、重试失败项或创建替代任务。
- 修改列定义形成新修订，新任务绑定新规则；旧任务不就地换规则。仅改某些结果走局部修正，不能为了局部调整悄悄改变全列含义。
- 支持“删除重来”的可恢复操作：将旧任务/草稿列撤出当前工作面，预览依赖影响并确认，建立替代关系；历史版本与审计保留。永久清理另行处理。

## 三、阶段2：让对话能完成圈范围、确认和提交

### 4. 服务端查询范围，展示范围与执行范围分开

- 增加条件查询/范围预览MCP与业务接口：原字段条件、标签值、失败/未知/待更新状态、某任务未完成项、复合条件。
- 支持“件数标签=2”“只修正尺码失败行”“主色是蓝色但冷暖标成暖的行”等。模型提出条件，应用验证字段、运算符、数量及样例，并生成稳定范围引用。
- 全量范围有明确入口，不要求模型枚举352个ID。确认时冻结商品集合与列修订；若预览后范围变化，提示刷新影响，不能偷偷扩大。
- 新增标签的默认执行目标仅包含本提案新增/修订的列；显示旧列不影响执行。多列执行由专门的标签选择器决定。
- 局部覆盖提案展示已有值、候选值、是否重看图和人工修正数量；人工优先保护保持不变。

### 5. 一份复合提案，一次明确确认

- 标签定义/修订、列间依赖、执行商品范围、抽样或全量、覆盖及图片策略组成一份可审阅提案；新列用临时引用，在确认事务中解析稳定ID并创建任务。
- “讨论方案”不要求先写入正式列。方案确认后直接执行，无需先去右边建列再回左边确认。
- 绑定到当前明确提案的确认按钮/确认指令由应用识别；不让模型自行制造确认。存在多个提案或“确认”对象不清楚时在同一入口澄清。
- 修复CLI ask与网页的桥接，普通澄清不触发权限错误；无需开放Shell、文件写入或子任务权限。
- 对话报告执行状态前读取实际任务摘要；可用操作来自真实工具目录。禁止声称并不存在的删除界面、图片能力或“同批零增量成本”。
- 同一数据集继续复用一个Reasonix会话，更新规则后恢复并验证工具能力。

### 5A. 表格核对、统一筛选和空间布局（补充体验要求）

此项纳入阶段2，与范围查询共用一套条件模型。当前页面行高101px、缩略图约77×82px，下方任务列表持续占用高度；不能仅在现有单列“包含”框旁边再加一个独立筛选器。

**图片核对**

- 双击商品图片打开大图查看器，加载已导入原图而非把表格缩略图放大；支持适应窗口、100%原始像素、滚轮缩放、拖动平移和Esc关闭。
- 显示商品标识、原始行号、图像尺寸及来源；有多图时可切换，支持按当前筛选/排序结果查看上一件、下一件。
- 原图分辨率不足时明确显示实际尺寸；“高清”不代表算法补细节或自动改写远程图片URL。已有更高分辨率的可信原图可按原有图片获取能力提供，加载失败保留现有图片与明确提示。
- 图片双击与区域选择、单元格编辑分开处理；关闭查看器保持表格滚动、筛选和选中位置。

**Excel式表头筛选**

- 原始字段与标签字段都在表头提供筛选入口，入口与排序、拖动列宽不冲突。图片列提供有图/无图/加载失败等适用条件。
- 下拉列出该列实际不同值及商品行数，支持搜索候选、全选、清空勾选、勾选多个值、应用、清除此列筛选。全部不勾选并应用表示零行，不能等同清除筛选。
- 同列勾选值按“或”匹配，多列条件按“且”匹配。属性列提供✓、❌、空白，未知/待处理/失败/待更新作为独立状态条件，不能和已完成空值混为一谈。
- 候选数量按其他列条件已经生效、暂不应用当前列条件的范围统计，显示口径说明。保留已勾选但当前数量为0的值，方便取消；多值候选按商品行去重计数，不擅自按字符串拆正式属性。
- 生效表头同时显示强调色和实心漏斗；顶部显示“已筛选N列、显示X/总数行”及各列条件摘要，可逐项清除或一键清除全部。隐藏的列仍有条件时，摘要持续可见。

**独立筛选按钮**

- 打开同一份筛选状态，默认选当前列，也可选择任一原始列/标签列；支持“包含”关键词匹配，默认按显示值转文本后匹配，忽略英文大小写。可附加等于、不包含、为空等常见运算。
- 例如指定“套装件数”列，分别输入2、2件、件套或2件套，都能匹配显示值“2件套”。数值型2可被关键词2匹配，但没有确认的单位映射时，不把原始数字2自动伪装为字符串2件套。
- 多关键词提供明确的“任一/全部”选项。若同列同时有勾选条件与关键词条件，两者取交集，并在摘要里完整展示；表头下拉中的候选搜索只搜索选项，不暗中修改已应用的行条件。
- 表头与按钮实时互相反映已应用条件，不能出现两套不同结果。与全局搜索组合时同样显示其生效状态；筛选后安排任务通过同一个服务端解析器冻结范围。
- 按数据集保存筛选条件，重开时明确展示条件摘要与恢复提示；查询/版本切换时验证字段身份，不让不存在的列或旧版本条件悄悄过滤数据。
- 模型结果增量写入可能改变匹配行数，应保留稳定滚动与选中身份；执行确认时使用冻结范围，不随之后筛选结果增减而扩展任务。

**布局：常规视图＋表格专注模式**

- 常规视图保留左侧对话，允许拖动调整宽度或折叠；下方执行任务默认收成一条状态栏，显示运行/待处理问题数，点击展开任务抽屉，展开高度可调整。
- “表格专注”一键收起对话和任务详情，让表格占满应用主要区域，保留紧凑工具栏、固定表头、商品标识/图片及任务状态入口；可显式返回，打开图片优先由Esc关闭图片，再退出专注模式。
- 任务完成或失败更新状态栏提示，不自动弹开抢占表格或遮挡正在核对的单元格。新提案显示入口提示，随时可回对话查看。
- 切换布局保留筛选、排序、列宽、统一行高、滚动和已选商品；任务继续后台运行。窄窗口工具分组收纳，避免多行工具栏挤占表格高度。

**统一行高/显示密度**

- 工具栏提供紧凑、标准、大图三档（拟定48/80/120px，按实测微调），以及40–200px自定义统一行高。用户要求的行间距以整行高度控制，同时调整上下内边距及缩略图尺寸。
- 设置作用于当前工作表所有商品，包括筛选隐藏的行，按数据集记忆。文字限制行数，超长内容通过展开/详情查看，避免长标题把统一行高撑开。
- 缩略图保持比例、不裁掉商品；大图查看器独立于行高。调整后保留当前行定位，确保固定列对齐、编辑控件可用。

## 四、阶段3：改善视觉准确性与执行效率

### 6. 联合证据和可执行标签规则

- 提案显示实际输入来源：哪些原字段、哪些图片、已有底稿和上游标签。文字多列联合读取；图文任务将相关文字证据与图片共同用于判断，并保存来源冲突。
- 对图文联合任务选用真实支持相应输入的请求路径，不能把“图片先压成一句描述”直接当作充分的图文联合能力；视觉观察不足时保留补充请求机制。
- 对同一商品、同批已确认的视觉标签合并提取要求，一次观察覆盖所需部件/维度；按图数、输入长度、输出复杂度拆批。跨列缓存依据证据覆盖而复用，新维度不足再识别。
- 视觉证据结构包含套件/部件、位置或区域、可见性、观察、未知原因；支持已导入的多张图，按需选择补充视角，不能仅固定取第一张图。
- 修正规则中的不等价同义词与“越不确定越具体”。区分图案元素/排列/风格、肩带宽度/背部走向等可能交叉维度，按当前用户目标提少量建议。
- 增加明确的单选/可多选约束。保留默认多属性命中触发整类拆列提案的要求；明确互斥单选类别若冲突应待确认，不能自动拆。确认拆列前展示表头变化、触发行和证据。
- 已拆列支持经过确认恢复单列，多个命中无法无损合并时展示受影响行及归并方案；原观察保留，不偷偷截断。
- 定义中的条件依赖落实为程序依赖与校验，例如纯色行不应填写印花花型；修改上游触发正确的待更新/重算。
- 以泳衣实际错例建立小型判别样本集，记录旧观察/旧值、新规则/新值；未知不计作正确命中，结构通过不计作语义正确。

### 7. 缩小事件与记录首次耗时

- SSE只发送变动单元格、进度计数、状态和简短错误摘要，完整冻结规则按ID查询；任务不可变输入只保存一份。
- 新事件写入立即采用紧凑格式。历史大事件先备份并制定可回滚归档策略，不直接清空或无提示压缩正式库。
- 分开记录底稿、视觉、填表、排队、保存及界面更新开销；保留跨重试累计请求数、失败数与缓存命中。
- 使用同机同模型同数据的冷缓存/首次执行与复用执行分别比较；三列任务验收重点为共享观察后请求减少和语义结果一致，不能预先承诺一定一次请求或零增量成本。

## 五、阶段4：全局理解与有来源的知识辅助

### 8. 基础全局画像与按需视觉概览

- 上传后基于原文和字段统计生成覆盖率、缺失、重复、属性分布、冲突概览，注明哪些来自全量统计、哪些来自抽样、底稿完成比例。
- 按不同文本属性、图片指纹和异常类型选择代表性样本，形成视觉概览；缺少视觉覆盖时明确展示，不把文字抽样称为已看全局图片。
- 可选抽样数量默认min(20,选定商品数)，采用可复现的代表性选择，避免一直取前20行。
- 画像用于指导当前标签设计、发现候选缺口和安排补充观察，不阻塞用户直接执行，也不自动生成全部标签列。

### 9. 可追溯知识检索

- 从当前问题、品类和用户目标出发检索产品术语、结构分类、使用场景等参考信息，优先原始/可靠来源；先返回少量相关关注点。
- 资料保存来源链接/出处、获取时间、适用范围、摘要和用户修正；支持读取用户已有资料与复用经过确认的项目知识。
- 外部资料只解释术语、提出灵感或规则依据；本商品标签仍需本商品证据。不能用通用品类知识补写商品不具备的事实。
- 将检索请求、结果来源和执行规则分开保存。检索失败有明确状态；不得声称已查询却实际只用了训练语料。
- Skill补充字段目录、范围查询、提问/确认、联合证据、失败诊断、知识来源的规则；MCP开放相应受控能力，并做真实调用验证。

## 六、验收、迁移和上线

1. 保留现有数据库和下午错误现场，迁移前一致备份；先在隔离库用现有352行副本复现，再按阶段验证。延续SQLite、已有模型授权和图片格式，不扩展多人协作。
2. 制作同内容不同表头/不同顺序、多个参数列、歧义编号、月销量/累计销量的变体文件；验证原文完整、识别用途、歧义提示、图文来源及导出，不只测硬编码别名。
