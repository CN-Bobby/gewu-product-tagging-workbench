# 关键词调研（工作台内置的第二个工具）

状态：0.5.0-beta.7 之后的一轮整合。打标页面不动，新增一个与它并列的顶级入口。

## 入口与边界

顶栏「关键词调研」进入，进去后有「返回商品打标」退回主页面。它和打标的关系是**并列**的：

- 不绑定数据集、不读写标签与草稿、不写 `batch_job`、不加打标数据库表（`schema_version` 未变）
- 运行状态是**文件式登记**，落在当前实例的数据目录 `<数据目录>/keyword-research/<run_id>/`
- 与打标的数据联动**本轮不做**，只保留运行记录

## 第一次使用：填 SellerSprite MCP 密钥

页面上的密钥卡填入 SellerSprite 的 MCP `secret-key`（**必须由用户自己填**，程序不代填、也不从别处复制）。它落在当前实例数据目录下的 `keyword-research/credentials.env`：

- 只写不回显：接口只返回「是否已配置」与写入时间，任何部分都不回显，不写日志、不进运行记录
- 不放 Reasonix 的 `config.toml`：那个文件被模型设置无条件遍历并回写，塞一条没有模型的 provider 会在模型设置页多出空行

模型（LLM）**复用工作台已有的模型服务**，不新增第二把 Key：用你在「模型设置」里配好的默认文本模型。

## 一次调研怎么跑

1. 填表：站点（下拉来自后端白名单）、ASIN（可粘贴多行）、可选 Node、`Top` 口径、数据月份、矩阵月份
2. **核算预算**：返回预计 MCP 调用次数与硬上限。矩阵开关会改变这个数字（见下）
3. **确认发起**：必须带上核算得到的 `plan_hash`；预算变了会被拒绝，避免拿旧预算的确认去跑新参数
4. 看进度：阶段推进 + 每次取数的结果（成功/失败/被截断/限流等待）都在日志里
5. 完成后下载 Excel 产物

**同一时刻只允许一次调研在运行**（限流器是每次运行一份、调用日志是进程内锁，串行才不会撞服务端限流）。

## 矩阵开关（本轮新增）

「是否产出两个 ASIN 矩阵」勾选与否改变**两层**东西，不只是少画两张表：

| | 勾选（默认） | 不勾选 |
|---|---|---|
| 报告 Sheet | 13 张 | **11 张**（不含 `08_ASIN自然广告位矩阵`、`09_ASIN流量占比矩阵`） |
| 取数 | 每个 ASIN 一次 `traffic_keyword` | **整条链路跳过该调用**（调用量最大的一环） |
| `06_集中度与机会矩阵` | 含矩阵区 | 只保留关键词行 |
| 预算 | 含矩阵调用次数 | 预算里对应项为 0 |

不勾选时，`12_数据质量` 会写明「本次未勾选矩阵」，与「纯 Node 模式（输入里没有 ASIN）」是两回事，不会混用同一句文案。产物少两张表是**预期**，不是数据缺失。

## 调用量与限流

- 滑动窗口 8 次/60 秒，最小间隔 7.5 秒
- 一轮 20 个 ASIN 大约 24+ 次调用（每 ASIN 一次矩阵 + 批量反查 3 页 + 趋势词），**纯等待约 3-4 分钟**
- 服务端限流（`接口访问次数已达上限`）会等待 60 秒后重试一次；权限/额度/参数错误不重试

## 记录在哪

每个运行一个目录：

```
<数据目录>/keyword-research/<run_id>/
  input.json      本次口径（含矩阵开关），一次运行的事实来源
  plan.json       核算与确认，运行中会被实际趋势词数更新
  run.json        状态/阶段/产物名+字节+sha256/失败原因，以及引擎资产哈希与所用模型身份
  events.jsonl    追加式事件日志，SSE 按 sequence 续读
  raw/            每次 MCP 原始响应（含调用元信息）
  cache/          中间结果与 call_log.json（每次调用的工具/范围/成功/条数/是否截断）
  logs/run.log
  output/         报告产物
```

密钥只出现在 `credentials.env`，上面这些文件里一律没有。

## 用户亲手验证（不需要重装）

1. 双击 `构建测试版本.cmd` → 等它输出 `builds/0.5.0-beta.7+<sha12>-dirty.<hash>` 并自动打开工作台
2. 顶栏应出现「关键词调研」→ 点进去，页面应正常渲染（不是空白/报错）
3. 站点下拉应列出后端白名单（19 个站点），**不是前端硬编码**
4. 什么都不填直接核算 → 应一次列出**全部**校验问题（站点为空、至少一个 ASIN 或 Node 等），不是只报第一条
5. 密钥卡填一个错值再删掉 → 应显示「已配置」→「未配置」，且页面上不回显密钥内容
6. 真正跑一轮需要：有效的 SellerSprite MCP 密钥 + 已配好的模型服务。**离线不消耗调用配额**的验收走自动测试（见下）

**失败判定**：页面报错时按提示看 `run.json` 的 `error` 与 `events.jsonl` 末尾；数据目录下的 `logs/` 里若没有对应运行目录，说明请求没到后端。运行中的实例若被强杀，下次启动会把遗留的「运行中」如实标为**已中断**（不假装还在跑）。

## 自动验证

```powershell
.venv\Scripts\python.exe -m pytest -q                      # 后端（含关键词调研的离线端到端）
cd frontend; npm test                                      # 前端（含事件名跨端守卫）
```

离线端到端用**历史真实录制的 32 份 MCP 响应**跑完整流水线并产出真 Excel，不发起任何真实网络或模型调用，也不读真实凭据。

⚠️ **那批录制夹具不入版本库**（仓库审计禁止 ASIN 形状的字面量与模型响应原文入库），只存在开发机本地：`tests/fixtures/keyword_research/`（该目录已在 `.gitignore` 里）。没有夹具时，6 个依赖它的用例会**明确 skip**（不是静默通过），其余用例照常运行。要复现最完整的那一层证据，得先有这份本地夹具。

真实取数只在获得授权后单独跑一次。

## 报告模板

引擎原来自带一份报告模板 `.xlsx`。仓库不允许 `.xlsx` 入库，所以模板改为**首次使用时按需生成到实例数据目录**：

```
<数据目录>/keyword-research/report-template/keyword_market_report_template.xlsx
```

生成器是同目录的 `build_template.py`，实测重建出的模板与原来那份**同名 13 Sheet、尺寸一致、取值差异为 0**。模板不入程序目录——运行时往程序目录写文件会破坏「程序目录运行时零写入」这条不变量。每次运行会把所用模板的哈希记进 `run.json`（`report_template`），便于复核产物出处。


## 本轮已知限制

1. **与打标无联动**：结论不进打标数据集，也不参与标签判断（后续若做，走既有的只读引用或提案通道，不改「外部资料不成本商品事实」这条契约）
2. **第二条模型调用路径**：关键词调研保留引擎自身的调用语义（Responses→Chat 回退、截断拆半重试），与打标的直连批处理是两条路径；本轮不合并，避免把整合轮变成模型层重构
3. **桌面版冻结**：代码已由工作台接管，`sellersprite-keyword-app-rs` 不再演进；它若仍在别处使用，以后修复需人工同步一次
4. **关键词页上仍会显示数据集级的提示条**（notice/alert 属于打标页的状态）；尚未按页面隔离
5. 报告矩阵口径依赖引擎脚本；`validate_report` 的「13 张 Sheet」校验已按开关条件化（关闭时校验 11 张）
6. **录制夹具只在本机**：新克隆的仓库没有那批真实录制响应，6 个离线端到端用例会 skip；仓库里保留的离线假件是 `FakeLLM` 那一层
7. **报告模板按需生成**（不入库）：首次使用时生成到数据目录，生成器为 `build_template.py`
