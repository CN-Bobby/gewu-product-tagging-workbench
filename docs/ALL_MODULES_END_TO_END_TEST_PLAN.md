# 格物工作台全模块端到端测试方案

## 文档目的与当前边界

本方案定义如何对现有工作台做可重复的自动回归、浏览器流程、人工业务验收和有限的真实外部接口验收。它是执行方案，不是测试结果、发布批准或真实调用授权。

当前仓库主工作树位于 D:\数据打标项目，分支 feature/0.5.0-delivery，HEAD 为 2964ba1929ac；本次核查时该工作树已有大量未提交和未跟踪改动，且与 origin 相差 20 个本地提交。项目进度文档里的历史构建、测试数字和浏览器记录不能替代对当前代码的验收。本方案不覆盖、清理或提交这些既有改动。

## 1. 测试目标

对每个模块验证完整业务链，而不只验证页面能够打开或 API 返回成功：

1. 从用户输入开始，确认字段、站点、项目、数据集和任务范围正确。
2. 确认人工确认点、权限和任务状态正确，失败、取消、重试及恢复可解释。
3. 确认结果、报告和下载文件可用，来源、范围、版本和项目归属可追溯。
4. 确认共享模型配置与凭据快照生效，密钥不出现在数据库、日志、报告或截图中。
5. 确认 DEV、TEST、PROD 的代码身份和数据目录可以辨认，测试绝不写入正式业务数据。
6. 将确定性自动化、模拟接口浏览器测试、真实外部服务检查和业务语义验收分别记录，不能互相替代。

## 3. 环境与安全规则

### DEV

用于开发中的功能和短周期检查。代码可以变化，数据必须使用 DEV 专用目录。日常默认为离线；需要真实调用时，只针对一个模块开展一次有记录的专项检查。

当前 Run Center 的 DEV“真实接口验收”选择是**进程级开关**：选择后，该 DEV 后端中的模型、MCP、Amazon 等受门禁操作都可能发出外部请求。它还不能按模块、任务、请求次数或金额硬性限额，也不是逐任务弹窗授权。启用前要确认没有其他人或自动任务正在使用这个 DEV 实例；只发起本次目标任务，结束后停止该实例以撤销授权。

### TEST

用于人工验收一个固定提交。开始前确认构建清单中的提交、dirty 状态、构建 ID、数据路径和测试报告；验收期间不得让源码热更新或静默替换候选。TEST 的在线选择同样是进程级能力，不代表请求数/金额已被程序限制。

### PROD

不用于测试、演示、重置、迁移或错误注入。不得从测试工具指向正式目录，不得将正式数据库复制到 DEV/TEST 后再把其绝对路径或密钥写进报告。

### 运行前必须核对

- 从桌面入口打开后，读取运行状态：环境名、页面/API 地址、构建 ID、commit、dirty 状态、数据目录、凭据“已配置/未配置”、外部调用策略。
- 对 DEV/TEST 确认数据目录与 PROD 路径不同；健康信息或运行中心身份不匹配时停止测试，不要猜测当前页面连到哪个后端。
- 离线自动化只用临时目录、模拟 provider 和本地网络拦截；运行前清除 DEV/TEST 的 live-validation 环境变量。
- 人工验收数据使用合成小样本和经过脱敏、允许复用的复杂 Excel 样本。建议固定夹具根目录 K:\GeWuFixtures\project-library-v1，并在每次使用前核对 fixture manifest 和 SHA-256；若目录或清单不存在，不把历史目录当成已验收夹具。
- 重置只能针对 TEST 专用目录：先停止匹配身份的服务、显示将重置的绝对路径、生成备份并核对正式数据哨兵。验收报告存放在数据重置以外的位置。
- 任何 Key、MCP token、代理凭据、完整原始 ASIN 清单都不得出现在测试报告、截图或终端日志。

## 4. 测试数据分层

### A. 自动化合成夹具

使用少量可预测记录：商品表至少覆盖正常值、空值、重复 ASIN、父/子 ASIN、非空人工标签、图片缺失、图片存在、WPS 图片；评论表覆盖正/负/中性、重复评论、空评论、翻译失败；关键词和 VOC 模块使用确定性假 MCP/假模型响应；寻龙诀使用固定 Sorftime 响应与可重放请求账本。

合成夹具要求：

- 输入和预期输出均有稳定 ID 和版本号。
- 记录源文件 SHA-256、记录数、工作表数、列映射和 fixture 版本。
- 每个测试从空临时目录启动，结束后检查输出，不复用用户正在验收的数据。
- 假 provider 必须记录被调用次数和参数；测试断言调用次数，而不是只断言页面出现“成功”。

### B. 人工验收样本

使用经核准脱敏的狗狗玩具、泳衣和复杂 Excel 样本，验证真实格式、公式缓存、图片、WPS 图片、跨工作表、历史报告、空文件及样本映射。样本只读复制到 TEST fixture，不把源文件作为运行目录。

### C. 真实服务单项样本

每次只启用一个外部模块。记录目标站点/Node/ASIN 数、明确操作、预期服务、允许的最大工作量、是否允许重试及停止条件。若服务不能在调用前可靠估算工作量，先不执行真实任务，改用模拟夹具。

“一个任务”不等于“一次请求”或固定费用：评论、VOC、关键词矩阵和寻龙诀可能在一个任务中产生多次 MCP 或模型请求。

## 5. 分阶段执行门禁

### G0：环境和候选身份

1. 记录日期、测试人员、分支、HEAD、工作树状态、VERSION.json 版本。
2. 从当前桌面入口读取 DEV、TEST 状态；记录端口、代码来源、数据路径和 policy。
3. 确认本轮使用的是合成夹具或 TEST fixture，正式数据哨兵和备份记录已存在。
4. DEV/TEST 默认离线；若做真实单项测试，另写授权记录后再启动。

**通过条件：**身份和路径完整且隔离。无法确认环境、数据路径重叠、构建身份不一致时为阻塞。

### G1：确定性自动回归

在干净的临时目录运行当前提交的全部检查：

    .venv\Scripts\python.exe -m pytest -q
    npm --prefix frontend test
    npm --prefix frontend run build

再运行模块专项入口：

    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\test_product_archive_phase1.ps1
    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\test_amazon_voc_phase2.ps1

专项脚本运行前先审阅参数和默认行为，确认不会选择 Live 模式。需要定位缺陷时可只运行相关 pytest 文件，但提交验收结果前仍要运行完整离线回归。

**通过条件：**所有要求的测试通过；skip、warning 和环境限制逐项记录；构建产物身份与测试 commit 对齐。离线回归通过不代表真实服务或业务语义通过。

### G2：浏览器模拟端到端

在隔离 DEV 或 TEST 中启动合成数据和假 provider，浏览器网络只允许本地工作台、并拦截外部域名。验证实际点击、页面导航、请求字段、状态变化、产物下载和浏览器控制台。

至少覆盖：主导航所有入口；左侧项目树展开后仍留在当前页面；项目/文件夹/文件点击和浏览器后退/前进；档案映射确认门禁；下游 dispatch 使用选中数据；任务状态从创建、排队、执行、成功/部分完成/失败到取消；页面刷新和重启后恢复状态；窄屏下关键操作可用。

已有项目档案浏览器流程脚本会拦截关键词和评论 dispatch 并返回合成响应，证明的是浏览器到请求契约，不代表后端真实任务或外部服务已跑通。报告中要明确这一点。

### G3：分模块人工业务验收

在冻结 TEST 上按第 6 节逐项操作。每项记录：步骤、预期、实际、构建 ID、fixture 版本、截图/产物路径、产物哈希、通过/失败/阻塞、验收人。人工检查失败后回 DEV 修改，再生成新的 TEST 候选，不能边验收边换代码。

### G4：外部服务专项验收

只在自动测试和模拟端到端通过之后进行，并按第 7 节逐个模块单独授权。不要一口气启用所有模块或批量执行。启用期间记录 Run ID、外部服务类型、任务参数摘要、开始/结束时间、实际调用账本、模型 token/账单可取得值、输出哈希和停止原因；结束即停止该 DEV 实例。未取到可靠用量数据时写“未知”，不能估成零。

### G5：发布前安装/升级/回退

仅在 TEST 候选验收通过后进行。使用候选清单中的准确构建，在隔离 TEST 数据库上验证全新启动、旧 schema 到新 schema 迁移、凭据/会话状态、安装升级、程序替换和回退。升级前备份数据；回退后核验报告、任务检查点、数据哨兵及人工值不变。只有对应证据齐全才允许按 RELEASE_GOVERNANCE 更新发布状态。不得覆盖 beta.7 历史构建或复用客户版本号。

## 6. 分模块人工检查清单

### 6.1 商品打标与 Agent

- [ ] 导入合成/脱敏工作簿，选择或创建项目；确认数据集、工作表、行列和图片数正确。

- [ ] 切换数据集后核对 Agent 会话和草稿归属，不将上一个数据集的会话误显示为当前会话。
- [ ] 创建标签建议，检查标准、样本范围和风险；未经人工确认不能写入正式列。
- [ ] 确认后先抽样，再启动小批文本/视觉任务；核对任务冻结的模型/凭据身份、进度、取消、失败和重试。

### 6.2 项目管理与文件树

- [ ] 创建项目后出现四类固定文件夹；空类别显示为空，不虚构文件。
- [ ] 从打标、关键词、评论、VOC 产生的已归档成品都归属正确项目；过程文件不误列为成品。

- [ ] HTML 报告在隔离 iframe 中预览；脚本不执行；错误/缺文件/哈希不符时不提供错误文件内容。
- [ ] 外部历史登记只显示允许的元数据，不泄露绝对源路径；下载内容与登记哈希一致。

### 6.3 选品档案

- [ ] 关联已有 Dataset 与导入 SellerSprite 工作簿各走一遍；确认项目选择和样本行数。

- [ ] 源文件变化后旧映射失效并要求重新确认；不改写、不删行、不自动去重源数据。
- [ ] 用边界夹具核对重复 ASIN 统计、空值与不可解析值、销售额估算标记、区间下界/上界和 Data X 标签筛选。

- [ ] 评论原文和 VOC 子页只显示与档案/项目关联的任务及当前 revision；缺少来源覆盖时显示未知，不推断覆盖率。

### 6.4 SellerSprite 关键词调研

- [ ] 下载工作簿，核对关键词来源、趋势、站点/月、摘要统计、运行 ID 和错误明细。
- [ ] 部分失败必须标为部分结果，不能只凭文件存在判定完整成功；重试不重复已成功且已保存的阶段。

### 6.5 Amazon Listing 图片采集

- [ ] 用假 HTTP/浏览器响应验证站点解析、重复 ASIN 去重、队列 FIFO、最多两个任务组运行、第三组等待、取消后补位。

- [ ] 验证产物只含 Listing 图片，不把功能描述为 A+ 或 Brand Story；每商品图片数量、格式、大小及错误项符合当前限制。
- [ ] 单个结果工作簿可下载并导入为新工作表；图片成为主图/补充图的对应关系正确。
- [ ] 真实网络仅用一条用户授权的 ASIN；出现验证码或限制时停止，不自动绕过。

### 6.6 Amazon 评论

- [ ] 用假 Sorftime 验证榜单/手工 ASIN 两类入口、站点冻结、任务并发、进度、取消、重试、断点恢复和请求去重。
- [ ] 核对评论调用是每 ASIN 两次 Both 采样，不把它误记为分页；每次最多 100 条且时间范围为最近一年。
- [ ] 核对原始响应、评论去重、翻译覆盖、情感映射、三张工作表和汇总计数。
- [ ] 部分采集任务明确标注成功 ASIN、失败/未完成项和数据范围；下载内容哈希与项目文件登记一致。
- [ ] 若进入 VOC，先下载并人工检查评论 Excel，再明确点击启动；只使用该工作簿，不暗中增加第二数据源。

### 6.7 Amazon VOC

- [ ] 拒绝多文件、错误扩展名和超 50 MiB 输入；项目的市场、国家、语言和品类与运行快照一致。
- [ ] 用固定假 provider 验证完整多阶段分析、失败阶段恢复、取消、重试、重启恢复和幂等交接。
- [ ] 打开 HTML 报告；核对六个洞察模块、Excel 十二个工作表及质量报告的契约、证据引用和计数。
- [ ] 人工修改评论事件后产生新 revision；旧 revision 保留，可对照，下载对应最新 revision。
- [ ] 不从外部补采评论；部分评论来源按实际工作簿范围分析，并在报告中展示来源范围。

### 6.8 寻龙诀

- [ ] 用模拟 Sorftime 响应验证 Node/站点、策略、建 Run、请求账、SQLite 检查点、暂停、显式恢复、取消和报告下载。
- [ ] 树节点、分支、趋势、机会、淘汰和剪枝数量与输入账本一致；所有失败分支都显示，PARTIAL_DONE 不标成完整成功。
- [ ] 重启只恢复协调状态；未显式点击恢复前不发新 MCP 请求。
- [ ] 真实验收只选一个明确范围的站点/节点和最低适用深度；多请求扫描必须先给出调用预算和结束条件。
- [ ] 对 No data available 等语义未获服务方确认时保留条件，不将技术成功等同于机会判断已通过。

### 6.9 总设置、凭据和运行状态

- [ ] 文本与视觉模型身份、凭据引用和端点在任务创建时冻结；已有任务运行中不被设置变更改写。
- [ ] 重启 DEV/TEST 后凭据只显示“已配置/未配置”；测试中使用假 Key 检查日志、报告、异常堆栈和备份没有明文。
- [ ] 配置缺失、撤销或无效时给出可恢复错误；不能悄悄切换到另一把 Key。
- [ ] 运行状态准确显示 profile、commit、dirty、端口、数据目录、policy、凭据配置状态和最近测试报告。
- [ ] 浏览器改动路由或展开项目树后，地址和页面保持一致；后退/前进、窄屏、刷新和重启恢复均可操作。

## 7. 有真实服务时的单模块范围建议

以下是测试设计建议，不是自动执行限制；启用 DEV 的 live-validation 后，当前进程门禁不能阻止其他模块被点用。

| 单项 | 建议最小范围 | 预期风险和停止条件 |
| --- | --- | --- |
| 模型文本/视觉 | 仅一个小样本、一个明确功能；文本与视觉分两次验；不跑全表/24 或 60 件扩样 | 一个业务任务可能包含多次模型请求；运行中遇到重复重试、输入明显超预算或 Key 身份不符立即取消 |
| SellerSprite | 一个站点、一个 ASIN、关闭矩阵、先生成预算计划；只启动一轮 | 单次查询仍可能产生多工具调用；出现扩量、额外月份或无法解释的请求时取消 |
| Listing 图片 | 一个 ASIN、一个站点、只抓 Listing | CAPTCHA、429/503、账号验证或站点范围变化即停止 |
| Amazon 评论 | 一个 ASIN、一个站点；先核对可能最多两次 Both 评论调用及翻译工作量 | 一份 ASIN 可返回较多评论并增加模型翻译；若不能确认最坏工作量，先用假 provider |
| VOC | 一份固定的 5–10 条脱敏评论工作簿、一个项目、一个 revision | 分析分多个阶段并可多次调用模型；不直接拿完整评论大表做首次真实测试 |
| 寻龙诀 | 一个站点、一个小范围目标 Node、最低适用深度；事先写明最大请求数和时间 | 不确定请求量或结束条件时不启动；达到任一上限即暂停并保存账本 |

真实运行必须使用隔离数据目录、事先核对待运行的具体功能和参数，并由业务负责人逐次同意。当前 Run Center 不能强制以上服务白名单或预算；若需要“超过上限自动停止”，应先实现和测试调用计数/费用门禁，再进行真实试跑。

## 8. 跨模块黄金路径

### E2E-A：项目、打标、Data X 与档案

1. 从桌面 TEST 入口确认冻结候选和隔离数据目录。
2. 选择固定狗狗玩具或泳衣验收夹具，建立/选择项目和 Dataset。
3. 确认字段映射，检查样本页和档案页指标。
4. 在打标页选取一小组夹具行；先看提案和样本，再确认并运行离线假模型任务。
5. 保存 Data X V1；继续修改一项定义并保存 V2。
6. 在项目树中找到原始数据和两个 Data X 版本，分别搜索、预览、下载并核对哈希。
7. 断言原始文件未改、人工非空值未改、Data X 版本不可变、档案样本数量一致。

### E2E-B：档案选品到关键词、评论和 VOC

1. 使用已冻结并确认映射的 Dataset，只选择清单中明确的 ASIN 行。
2. 核对站点、子 ASIN/父 ASIN 回退规则和评论策略，先用模拟下游服务验证提交字段。
3. 模拟关键词结果与评论工作簿落入正确项目，项目树只展示已登记成品。
4. 人工检查评论 Excel 后，模拟确认 VOC 交接；验证重复点击幂等，不创建重复任务。
5. 用假模型生成 VOC HTML/Excel/质量报告，修改一个事件生成新 revision。
6. 验证档案评论页、VOC 页、项目文件和报告的来源任务 ID、数据覆盖及哈希相互一致。
7. 只有前三个阶段全部通过，才由用户另行批准每个真实服务的独立小范围验收。

### E2E-C：Listing 图片到打标

1. 离线模拟单 ASIN 页面和图片响应，校验解析、下载、限制与 Excel。
2. 导入生成的工作簿为新 Dataset，检查主图和补充图绑定关系。
3. 用假视觉模型对一个商品运行标签草案，人工确认后保存 Data X。
4. 检查项目归属、图片 Asset、任务输入快照和输出下载哈希。

### E2E-D：寻龙诀独立扫描

1. 用固定回放响应运行小型模拟树扫描，核对状态、每一条请求账、断点和最终报告。
2. 注入一个分支失败和一次恢复，确认只重试未完成分支且整体状态仍为部分完成。
3. 验证没有显式恢复动作时请求数不增加。
4. 真实 MCP 扫描另立专项记录，不并入离线通过率。

## 9. 故障与数据安全检查

在合成/隔离环境注入：模型超时/鉴权失败、MCP 拒绝/断连、429/503、浏览器关闭、工作簿损坏、磁盘空间不足、重复提交、任务取消时有已完成项、重启前后有未完成项、文件 SHA 错误、缺少映射、项目被切换、无评论/全空评论、旧 revision 与新 revision 并存。

每个注入都要检查：

- 不把失败/部分成功伪装成完整成功。
- 已完成的付费调用结果、检查点和报告不会因重试或取消丢失。
- 重试只补缺失阶段；并发任务没有串数据集、串 Key、串项目或重复写入。
- 原始文件、人工标签、正式版本和源数据哈希没有变化。
- 输出明确的下一步，不泄露 Key、原始响应或本机绝对路径。
- 正式数据目录哨兵与哈希前后完全一致。

## 10. 报告格式与通过标准

每一轮保存一份不可覆盖的 JSON 摘要和人工清单，至少包含：

- run_id、测试时间、人员、环境、页面/API 地址、profile/policy。
- 软件版本、commit、dirty 状态、build ID、依赖摘要。
- storage/cache 路径身份（可脱敏）、fixture 版本和 SHA-256。
- 自动化命令、退出码、passed/failed/skipped、warning。
- 每条浏览器/人工用例的结果、截图/录像/下载文件路径与 SHA-256。
- 模拟或真实调用区分；真实场景的服务类型、任务 ID、调用数、模型实际用量/费用证据；未知项写 unknown。
- 数据哨兵前后哈希、重置/备份记录、报告自身哈希。
- 未解决缺陷、风险等级、人工业务签字和“可否进入下一门禁”。

必须区分以下状态：自动化通过、浏览器模拟通过、真实接口通过、业务语义通过、安装/升级/回退通过、正式发布。任何状态都不能由另一个状态推导。

**阻塞条件：**触及正式数据；身份或数据路径不明；秘密泄漏；外部请求超出书面范围；人工值被覆盖；任务恢复造成未授权新调用；报告把部分完成写成完整成功；测试提交与候选构建不一致。

**完整验收通过：**本轮自动化无未解释失败；跨模块黄金路径在隔离 TEST 完成；必测人工用例均有证据；真实服务专项若被授权则逐项完成或明确标为未做；报告及哈希完整；正式数据哨兵不变。外部调用未授权时，只能标记“离线/模拟闭环通过，真实接口和模型语义未验收”。

## 11. 推荐执行顺序

1. 核对环境身份、数据隔离和 fixture 哈希。
2. 运行全量后端、前端、构建和模块专项离线测试。
3. 运行浏览器模拟 E2E 与故障恢复检查。
4. 在冻结 TEST 上由用户执行 E2E-A 至 E2E-D 的人工业务步骤。
5. 对仍需外部验证的模块逐项另行授权，单项运行、保存用量和调用证据、结束后关闭 DEV live-validation 实例。
6. 汇总失败项和人工结论；修复后重新生成 TEST 候选并重跑受影响测试。
7. 只有准备发布时才执行安装/升级/回退和完整发布门禁。

本方案编写阶段只读取代码和文档，没有运行测试、启动服务、修改业务数据、调用模型/MCP/Amazon 或改变版本状态。方案对应的当前代码仍待在准确构建上按上述步骤实际执行。
