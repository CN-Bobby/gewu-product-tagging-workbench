# Amazon VOC 评论洞察

工作台内的 Amazon 评论 + VOC 统一工作流页，在费用优化实验分支中，新建任务使用 `amazon-voc-analysis` 的 VOC V2 分块抽取与综合契约。评论块逐条明确处理状态并通过覆盖门禁后，仅原子事件字段进入全样本语义综合；完整评论只保留在本地证据记录中。语义综合负责双语需求细分、旅程、比较和洞察，逐事件细分/阶段归属在独立的小批次阶段完成；高频词项可经单独的有界归并阶段抽象成规范概念，原词、映射和证据回链始终保留。缺失或无效归属按稳定 event ID 保守回退并留下审计计数。组合目标从评论拉取自动进入 VOC；仅 VOC 仍只接收一个评论 Excel。输入、清洗、证据和结论都来自该工作簿；市场、国家、语言和品类由项目设置提供上下文。分析不读取 Alexa、Customer Say、外部补全或其他评论数据。无模式标记的旧任务和显式保留旧模式的回归仍走 V4 多阶段流水线。

## 使用流程

1. 在主导航打开“Amazon 评论 + VOC”。
2. 选择现有 VOC 项目，或新建项目并填写站点、国家、语言和品类。
3. 选择总设置里的文本模型和已授权凭据，上传一个 `.xlsx` 或 `.xlsm` 评论表。
4. 查看任务状态。完成后可打开 HTML 报告、下载 Excel 证据库及查看质量报告。
5. 在任务详情检查评论事件；需要修订时保存修订说明，工作台会创建新 revision 并自动重跑。

HTML 报告包含六个评论洞察模块；Excel 证据库包含 12 个工作表。修订保留原 revision 供对照，下载链接始终对应当前 revision。

## V2 词项归并与正式细分门槛

- 正式细分至少覆盖 `max(5, ceil(评论数 × 1%))` 条不同评论，并有至少 3 条不同评论的有效引文。支持不足的候选会自动降为探索细分；细分还需说明与最相近候选在核心任务或成功标准上的实质差异。提示词要求相似需求先合并，不能按痛点、功能或措辞差异单独成群。
- 词典归并候选按不同评论数统计，只向模型发送最多 120 个高频候选值；模型只返回确认可合并的候选组。少于两条独立评论的长尾值不进入模型归并。归并失败或无法确认时，系统保留原值和原始映射，不丢弃、不猜测。
- 确定性归一只处理 Unicode 规范形式、大小写和空白差异；不会用字符串相似度自动合并语义不同的词。规范概念保留原词变体、支持事件和独立评论数，HTML 显示归一映射覆盖率，Excel 保留逐值回链。
- 符合条件时会额外产生一次有界词项归并请求，并纳入用量账本及阶段缓存；该请求不发送完整评论原文。其实际 token 增量和归并质量需要在新的真实模型运行后评估。本次代码回归不触发真实模型调用。

费用优化测试版的 HTML 报告保留 01 数据与方法概览；02–06 使用响应式卡片、章节导航和可折叠细分详情。细分名称、人群×场景×动机×任务、画像与 JTBD、使用者/购买者/关系/物理限制/角色诉求、痛点/痒点/期望及旅程阶段均由文本模型输出中英双语。模型按同维度信号抽象归并后再展示，原始事件与频次留在证据层；HTML 将零散计数收进可展开的回查区，Excel 的“细分需求”工作表呈现双语综合主题，原评论、事件、动态词典和映射继续用于审计。

## 从 Amazon 评论采集任务启动 VOC

在“仅评论拉取”目标中，评论任务生成 Excel 后可先下载人工检查；确认可用时点击“已检查，送入 VOC 并启动”。在默认组合目标中，评论工作簿生成后会自动交给 VOC。两种路径都使用总设置中的默认文本模型及已授权凭据。

每个评论采集任务只关联一个 VOC 项目和任务。VOC 直接读取评论采集任务生成的 Excel，不经过浏览器下载再上传，也不把原始 JSON 作为第二个分析源。重复点击或重试同一来源会打开已有 VOC 任务，不会重复启动模型分析。评论任务部分失败时，页面会提示工作簿只包含已成功采集的评论；人工确认后可按该 Excel 的实际内容启动分析。

## 模型、任务和数据隔离

- VOC 复用“总设置”中现有的文本模型端点、模型名和凭据解析及文本能力验证，不提供第二套 API Key 输入或存储。
- 每个运行只在 VOC 独立 SQLite 中保存模型引用和凭据 ID 快照；API Key 仅在任务进程内用于请求，不写入数据库、报告、API 响应或 VOC 日志。
- 评论原表、缓存、修订和结果存放在工作台 `TAG_STORAGE/amazon-voc/` 下，与商品打标任务数据及既有 Amazon 评论采集数据分开。
- 后台线程在工作台启动时恢复未结束的 VOC 任务，退出时停止调度；可取消排队/执行中任务，并重试失败或已取消任务。
- 只支持一个评论 Excel 文件，限制 50 MiB；站点、国家、语言、品类是项目设置，不是额外分析文件。

## Reviews + VOC 费用优化测试版

实验分支 `experiment/reviews-voc-cost-optimization` 将评论采集与 VOC 放入同一工作流页面，目标有三种：默认“评论拉取 + VOC”、仅评论拉取、仅 VOC。新建组合任务在评论 Excel 成功生成后自动启动 VOC V2；人工检查后交接和独立上传也使用 V2。VOC 失败时可从已保存的评论 Excel 和采集检查点续跑，不重复抓取评论。仅 VOC 仍只接收一份评论 Excel。

组合任务默认开启评论翻译，可在提交前关闭。工作区本地缓存按输入、模型、提示词、schema 和设置版本区分，默认保留 7 天并支持强制刷新。费用账本按评论采集、翻译及 VOC 阶段记录请求、重试、token 与供应商缓存用量；供应商没有返回费用时金额保持未知。缓存复用与供应商前缀缓存分别统计。

成本优化集成回归：

```powershell
python -m pytest tests/test_reviews_voc_cost_workflow.py tests/test_amazon_reviews.py tests/test_amazon_voc_reviews_bridge.py tests/test_amazon_voc_usage_metering.py -q
npm --prefix frontend test
```

真实模型对照使用隔离存储。语义门槛需由独立人工标注集判定；自动回归或模型自己的输出不能替代人工标注验收。该费用优化分支尚未合并到正式线，也未作为产品发布。
