# 商品通识打标 Skill 0.5.0 与格物工作台 beta.4

## 目标与边界

本版把前期服装、水杯、车载支架、首饰吊坠、儿童化妆玩具和儿童音频设备模拟中的共同问题固化为通用识别方法，不建立无限细分的品类百科。品类知识只用于提示观察点；单元格结论仍必须由本商品的图片、文字或确定性规则支持。

## 运行链路

```text
用户目标
→ 模式 + 维度 + 大类 + 产品形态路由
→ 只读取命中模块
→ 6–10件初始校准（每组≤6）
→ 跨组汇总 visual_standard
→ 必要时扩至24/60；全量需成本确认
→ 用户确认标签定义
→ 冻结 Skill、模块哈希、visual_standard、runtime_profile、输入策略
→ 每件商品共享视觉 observation_snapshot
→ 每批5件填表
→ 任务末集中 definition_gaps
→ 用户选择后一次性提出拆列/修订
```

## 模块体系

- 核心：证据确定性、实体与结论范围、多图校准、成本控制、运行契约。
- 模式：讨论建议、定义/校准、批量执行、失败修复。
- 维度：功能、结构与材质、主题、外观（形态/颜色/印花/纹理/表面处理与CMF）。
- 大类：服装、水杯、3C数码、家居装饰、收纳、工具、手工配件、玩具/活动套装、礼品。
- 形态：多组件、多变体展示、安装系统、同质集合、异质套装、电子系统、礼品套装。

## 兼容规则

- 旧任务继续使用自身冻结的0.4.x内容，不重新路由。
- 旧的文字、属性三态、中文归一和输出契约继续作为执行模块。
- 默认图片策略仍为`single_main_image_v1`，不会因补充套图出现而改变缓存或结果。
- `single_main_with_quadrant_crops_v1`、榜单截图用`screenshot_grid_crops_v1`与`main_plus_supplemental_v1`只能通过标签定义显式选择，并写入冻结配置、观察快照和复用指纹。
- `expansion_policy`只允许`never`、`end_of_task_suggestion`、`manual_only`；默认任务末建议，不再执行中生成提案卡。

## 验收门槛

1. Skill manifest、模块文件、案例JSONL通过专用校验及官方`quick_validate.py`。
2. 路由测试证明水杯颜色不会加载服装/电子模块，安装结构会加载对应形态包。
3. 标签确认后冻结的证据包含Skill版本/哈希、runtime profile、模块ID/哈希和视觉标准。
4. 代表图测试覆盖6件分组、失败二分、跨组标准和全量确认门槛。
5. 图片策略测试证明默认单主图，裁切策略一次发送整图与四区，缓存指纹不同。
6. 多值结果只生成任务末待整理特征；人工选择前没有自动拆列提案。
7. 后端全量pytest与前端生产构建通过后，才可把beta.4提升为客户候选；真实模型语义准确率仍需用人工标注案例集评估，不由单元测试代替。
