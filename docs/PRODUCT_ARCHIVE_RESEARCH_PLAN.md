# 选品档案深度研究实施计划

目标：在 K 盘 DEV 现有选品档案上实现模型主导的分步研究、公开资料核验、档案对照和高质量可编辑输出。设计依据见 `docs/PRODUCT_ARCHIVE_RESEARCH_DESIGN.md`。

> 2026-10-21 更新：此处保留原三阶段实现计划供追溯。当前工作采用 Reasonix Skill 与只读 Search/Fetch MCP；请按 [Reasonix 桥接说明](PRODUCT_ARCHIVE_REASONIX_BRIDGE.md) 核对正在实施的契约。

## 固定约束

- 保留 `K:\GeWuDev\Source` 当前全部未提交改动；不得修改 `D:\数据打标项目`。
- 不启动商品采集、关键词、评论、VOC 等任务；自动测试必须 mock 外网、模型和 MCP。
- 同一分析最多三次模型请求：初步研究规划、首轮发现整理、最终整体综合各一次；任何已提交请求都不自动重试。
- 首轮发现可根据真实抓取材料提出第二轮问题；抓取来源失败时必须标出，不能伪装为已覆盖。
- 每条结论可追溯来源；不把检索问题当输出关键词；关键词只来自档案关联的已完成任务结果。
- 资料少时允许基于模型知识推理，但标注推断和待验证事项；字段缺失必须有解释，不得静默留空并标成成功。
- 不递增 beta 版本、不提交、不推送、不发布、不更改 PROD。

## 实施任务

1. **分步研究计划与调用账本**：新增轻量初步规划和证据驱动的首轮发现整理；冻结文本推理模型与图像综合模型身份；规划和缺口整理使用文本模型，有图片时仅最终综合使用已验证视觉模型；记录三个阶段的模型、请求/用量/失败；规划阶段失败时按固定问题降级，不重试。模型规划少于四条首轮查询或三类分析问题时，自动补齐互补方向；补充和第二轮查询必须保留初始查询里的具体商品、人群锚点，避免泛化为大类泳衣。最终整体综合最多一次。
2. **两轮检索覆盖与来源质量**：初步规划生成首轮互补查询，发现整理只根据实际抓取材料追加第二轮核验问题；每轮和每个方向分配预算，整体最多 6 次搜索、12 篇网页、24 次真实 HTTP GET（包含重定向）；限制同一域名/重复页面占用；逐条记录查询状态、来源编号、候选数和失败原因。验证现实可用搜索后端；不可用时清楚降级，不声称完成联网调查。
3. **输入压缩与资料边界**：对四类允许资料按内容结构做高信息密度整理；对工作簿和图片路径增加敏感标识脱敏测试；提示词将所有来源内容视为不可信资料。缓存键加入模型身份和所选内容摘要。
4. **结果质量门禁**：支持产品形态比较、细分关系、统一模块数组或明确 no-data 原因；验证细分范围、跨模块关系、依据类型和来源编号；不完整结果应显示 partial 或明确失败原因，不能静默 ready。
5. **前端研究体验**：简洁显示研究问题、阶段、覆盖与模型/用量信息；实际输入和图片估计、最大调用预算、金额未知需在生成前可见；运行中的输入锁定；失败详情刷新后可恢复；保留整体决定和动态编辑。
6. **独立验证**：子代理分别提出并执行后端与前端测试；根代理复核 diff 和独立测试结果。运行定向后端/前端测试、构建、模拟浏览器宽窄屏及 DEV 热更新；之后用一次受控真实分析核对模型内容质量和实际用量，不运行收费采集/MCP。

## 每项完成证据

- 后端：假模型/假 HTTP 对三个模型阶段、两轮检索上限、规划失败降级、隐私、缓存失效、来源、partial 判定进行独立测试。
- 前端：mock API 的浏览器测试覆盖启动、研究进度、部分结果、刷新恢复、整体保留/忽略、动态编辑与 360/390px 布局；浏览器网络限制为 loopback。
- 构建：档案定向测试和 Vite build 通过；任何与本功能无关的全量失败另行说明，不扩大宣称范围。
- DEV：Run Center 的当前身份/build ID/commit/dirty/data path 与接口 runtime status 一致；浏览器显示热更新后的研究体验。
- 实际模型质量：记录运行 ID、模型、搜索可用性、问题/来源覆盖、输出 token 和是否截断；费用未知时不估称金额。业务内容需人工确认。
