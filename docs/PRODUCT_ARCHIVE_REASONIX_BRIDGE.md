## 已核对的复用部分

- Reasonix 官方 CLI 已提供一次性 `run --output-format json`、独立项目配置、Skill、MCP 工具与调用步数上限。工作台直接使用已安装 CLI，不另造智能体循环。[CLI 说明](https://github.com/loserbcc/reasonix/blob/main-v2/docs/CLI.md)
- DeepSeek 官方 Harness 已有 Search/Fetch API 提供者。工作台沿用同一公开 API 契约，在 Python 后端用一个仅含 `search` / `fetch` 的档案专用 MCP 适配现有 Reasonix；未复制 Harness 整套 Web 子系统。[官方实现说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-deepseek-api/README.md)
- 原先尝试使用 Reasonix 的 `@path` 图片引用，但该次运行记录无法证明视觉字节进入了模型。现在复用工作台已有的 OpenAI 兼容视觉调用格式，先用已验证视觉模型做一次客观图片观察，再把短描述交给 Reasonix 综合；不把文件路径当成已分析图片。[Reasonix 文件引用边界](https://github.com/esengine/DeepSeek-Reasonix/security)

## 当前路径

1. 页面只列当前档案关联的打标工作簿及图片、已完成关键词任务表格、评论任务表格、VOC HTML。用户可以取消选择；读取失败单独记录。
2. 后端冻结本轮模型与凭据编号，压缩已选材料，建立资料编号；业务关键词只来自已完成且已选的关键词任务。公开搜索词不会进入档案关键词模块。
3. 如选入关联图片且视觉模型已验证，先将最多 4 张图片作为图像块一次发送给视觉模型，只提取可见的形态特征；失败时明确记录未分析。随后每轮创建独立 Reasonix 工作区，载入 `skills/product-archive-research/SKILL.md` 与视觉观察短描述。该 Skill 引导一个连续研究会话：区分商品形态、提出问题、按需搜索与读取网页、综合资料，最终返回一个结构化分析对象。档案资料和网页内容均当作待分析数据。
4. 档案 MCP 只暴露 DeepSeek Search/Fetch，最多 6 次搜索、8 次网页读取，拒绝本机/内网和非 HTTPS 网址，不自动重试。只把成功读取正文的网页登记为可引用来源；失败记录保留状态。网页由 DeepSeek 远端抓取，远端重定向链的安全策略依赖该服务，本机只能验证提交的网址。
5. 后端分别校验 CLI 结果外壳、模型分析 JSON、字段与分群结构、来源编号和季节性依据。至少形成有效细分及三个可用分析模块时，其余模块缺失会列出原因，保留已有结论供整体审核；超过五个细分只提示复核，不整份丢弃。用户仍一次性保留或忽略，保留后可以继续编辑、增删和排序模块与条目。

## 费用与可见性

- `12` 是 Reasonix 最大工具调用轮数，不是模型请求次数或费用上限。最多 6 次 Search、8 次 Fetch；模型实际请求次数、token 与金额以本轮用量记录为准。未测得费用时显示“未知”。
- 图片最多 4 张，仅在模型设置中已验证视觉模型并选入关联打标表时进行一次视觉观察。若图片不可读取或视觉模型不可用，继续分析文本并记录未纳入原因。视觉观察会增加一次模型请求，Reasonix 仍可能发起多次模型请求。
- 不展示模型隐藏思维，只显示研究问题、检索来源与失败、支持来源的发现、完整建议和校验原因。
- 原始 CLI 结果和实测用量在解析之前落盘。仅当字段边界可唯一确定、修复不改写结论文字时，才允许修补结构边界；同时记录原文与修补后摘要及修补位置。失败任务可在资料指纹未变化时离线恢复为待审核结果，不再次调用模型或检索。
