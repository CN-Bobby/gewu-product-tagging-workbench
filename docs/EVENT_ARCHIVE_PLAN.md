# 历史事件归档方案

状态：方案已形成，正式数据库未清理。当前历史大事件约493 MiB来自早期完整表格快照；新事件已经按增量记录。不能把数据清理视为模型缓存清理。

1. 停止工作台，使用SQLite backup创建一致性副本并执行integrity_check。记录数据集、任务、版本和事件数量；在隔离副本先演练。
2. 只选择已结束任务所属、早于约定保留期的draft_event。消息、审计、结果证据、人工修正、版本快照和Reasonix会话不在清理范围。未完成任务和当前SSE游标仍需要的事件保留。
3. 按数据集与时间段写入压缩JSONL归档，包含事件原ID、类型、时间和完整payload；写入SHA256清单、行数、首末ID和源数据库构建标识。完成后重新读取并逐条校验，再允许清理副本。
4. 清理后保留归档索引与最早在线游标。SSE客户端游标落在归档区时必须明确发送reset事件并重新加载当前草稿，不能静默遗漏。该兼容逻辑验收前不删除线上事件。
5. 隔离副本验证版本内容、单元格来源和任务详情不变，浏览器断线重连可恢复，归档可查回原事件。记录归档前后主库、WAL和归档总空间。VACUUM仅在服务停止后运行，并预留至少一个数据库副本所需空间。
6. 用户审阅隔离演练结果后，按同一流程处理正式库。归档文件属于长期审计数据，不纳入10 GB可清理缓存，不自动删除。

本轮没有执行正式历史事件删除，也没有以仅压缩数据库文件冒充可追溯归档。
