# 干净Windows验收记录模板

状态：待真实环境执行。此文档不是测试通过证明。

记录Windows版本和架构、机器是否已有Python/Node/Reasonix、安装包SHA256、release-manifest的commit、版本和测试日期。使用隔离测试授权及明确标识的测试商品；不要把密钥、原始客户数据或完整会话打包进报告。

|步骤|操作与必须保存的证据|结果|
|---|---|---|
|安装|普通用户运行安装包，中文及空格路径；记录界面、程序目录、快捷方式|待验收|
|首次启动|快捷方式启动、选择独立数据与缓存目录、浏览器模型配置；证明无需系统Python/Node/CLI|待验收|
|重复启动|重复点击只打开已有工作台；另一程序占用端口时可用新端口；同一目录由另一版本占用时明确拒绝|待验收|
|业务|10行导入、件数零视觉、双击修改、模板复制、人工来源、V1/V2与Excel图片保留|待验收|
|会话|5条消息同会话ID与进程，停止重启后原ID和记忆恢复；另一上传独立会话|待验收|
|升级|停止旧版、安装新版本、检查数据库和会话备份、旧V1不变|待验收|
|回退|离线恢复工具保留新状态后恢复旧数据库与会话，打开对应旧程序，核对原会话ID|待验收|
|缓存|记录分类占用，清理仅移除可重建缓存，原表/图/结果/会话仍在|待验收|
|卸载|服务停止后卸载；程序文件移除，数据与会话留存；服务无法停止时卸载中止|待验收|
|更新|实际HTTPS清单可访问，版本比较正确；无网络时明确失败，无假更新成功|待验收|

每个通过项目必须附真实日志或截图文件及SHA256。发布证据JSON绑定相同commit/version，gates包含automated、browser、real_model、performance、clean_windows、install、upgrade、rollback、update_manifest；每项有status、artifact与sha256。scripts/check_release.py会拒绝缺失、其他构建或校验不符的证据。
