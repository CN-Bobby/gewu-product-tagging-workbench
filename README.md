# 格物 · 商品打标工作台

开发和交付状态以 [交付台账](docs/DELIVERY_STATUS.md) 为准；版本规则见 [发布管理](docs/RELEASE_GOVERNANCE.md)。根 `VERSION.json` 是唯一应用版本来源。开发分支版本不代表当前服务已部署或已通过发布验收。

本机 Excel 商品打标应用。左侧持续 Reasonix 对话，右侧一张累积标签的工作表；SQLite 保存在本机，使用 Reasonix 已有模型授权。

## 启动

双击 `启动工作台.cmd`，访问 http://127.0.0.1:8765 。已有旧页面需刷新一次。

开发环境：Windows、Python 3.14、Reasonix CLI 1.25.1、Node.js。已准备 `.venv` 和前端构建文件。重新安装或构建：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
cd frontend
npm ci
npm run build
```

模型服务配置和密钥仍由本机 Reasonix 管理，应用不复制密钥。文本和视觉模型可在右上角分别设置。一个数据集保留一个原生 Reasonix 会话 ID，进程持续复用；服务重启后恢复同一会话。已有数据集的对话保持原会话模型，设置中的文本模型同时用于后续填表。

## 日常工作

0.3.0 新增 `skills/product-tagging` 商品标签工程 Skill。上传后后台优先联合拆解 SKU、详细信息／详细参数、商品标题，点击“文字底稿”查看原文依据、未知和冲突；旧数据可在这里手动补充提取，不自动重新打标。任务列表中的“上传文字拆解”可以暂停、继续和取消。

标签最初仍为种类列。出现多个明确命中时，左侧生成“整类拆列”提案，确认后展示“种类－具体属性”：✓ 为明确命中，❌ 为明确不命中，空白保留未知及处理状态。属性单元格双击使用三态选择器，导出只附加勾选的属性列。首次文字预处理有独立耗时，后续复用底稿；不会把预处理缓存命中当成首次打标速度。

1. 导入带嵌入图片的 `.xlsx`。支持本次 `测试10行.xlsx` 的 WPS DISPIMG，以及普通浮动图片。
2. 在左侧讨论目标，例如“只从文字提取套装件数，用中文值”。Reasonix 先读取工作表，再生成变更提案。
3. 点击“确认变更”后标签成为草稿列。可以继续聊天修订定义，或在“安排打标”生成执行提案。
4. 执行范围可选全部商品、当前筛选结果、勾选商品；列范围由本次明确勾选决定，不会因为旧列仍可见而自动带入。确认时自行选择“直接执行”或抽样 `min(20,选定商品数)`。
5. “将主色系聚合为冷暖色”同样在对话中提案。确认映射后新增派生列，程序直接计算。
6. 表头点击排序，边缘拖动调整列宽。“列管理”选择标签和原始字段，“筛选”按标签值筛选。拖选单元格后复制，粘贴到 Excel；单击查看证据，双击直接修改，Enter 保存、Escape 放弃，清空保存为未知。
7. 满意后主动“保存版本”生成 V1、V2。草稿仍可继续编辑，正式版本冻结标签定义、映射、结果、证据与人工修正；版本下拉查看冻结表，“比较”查看版本之间或与草稿的差异。
8. 导出保留全部原始字段及图片，勾选追加标签并调整顺序。输出 `Product_Result`、`AI_Detail`、`Tag_Dictionary`，可导出草稿或正在查看的正式版本。

提案按钮是真正的业务确认入口；先点选一个待确认提案，再发送精确指令“确认执行”，也可确认该提案。普通对话里的“已经确认”等模型文字不产生批准。MCP 没有批准、保存正式版本或直接写单元格的工具。

## 执行与状态

- 默认每批 5 件、3 个并发请求；填表直接请求模型，商品不再各开一个 Reasonix 对话。旧的逐商品执行 HTTP 入口已停用。
- 0.5.0-beta.1默认关闭自动视觉标签的新建、确认和执行入口；图片导入、高清双击查看、人工核对和已有视觉结果继续可用。内部验证需显式开启`TAG_ENABLE_VISUAL_TAGGING=1`。
- 标签结果明确区分开放单值、枚举单值、多选枚举和布尔拆列。开放数字值不要求候选列表；`Size: 4`、`4T`、`3-4T`等明确尺码由程序提取和映射，不调用模型。
- 映射和数值区间由程序计算。改动上游单元格后，确定性派生列重算；需要模型的派生列标记“需要重算”并生成执行提案。
- 显式区分待处理、未知、失败、需要重算、待确认。跨多列修复保存不可变的逐列单元格范围，确认时不会生成列×商品的笛卡尔积；后续任务接管或人工修正后，旧失败任务自动进入已收尾状态。
- 暂停和取消不再派发后续请求；已发出的请求先返回并保存成功结果。因此按钮不是瞬间中止远端计费请求。暂停完成后可继续；取消后可提出新的执行提案。
- 执行规则在提交时冻结。执行开始后的人工修改和上游变化受保护，过期后台结果保留为冲突候选。单元格详情中查看候选，人工修改决定最终值。
- 保存版本前需等待运行、暂停中、取消中的写入结束，防止不一致快照。
- 任务详情显示请求数、视觉请求、缓存命中、请求累计等待、排队与保存计时。并发累计请求时间不能直接从墙钟时间中相减；视觉时间属于模型时间的一部分。
- 前端使用 SSE 增量接收聊天片段、变动单元格、提案和任务状态。断线从事件 ID 续传，取消旧版每两秒全量刷新。

模型结果仍是模型建议。证据栏保留原文和来源，人工修正优先；本次自动验收不代表商品语义已经逐条人工审核。

## 迁移、数据与恢复

原始文件不改写，保存于 `storage/originals`；图片保存于 `storage/assets`。正式库是 `storage/workbench.db`。商品标识按有效ASIN、有效SKU、父ASIN、原始行号选择；空白与数值0不作为SKU，原值仍完整保存在原始字段中。

首次迁移前通过 SQLite backup API 生成一致备份；本次备份位于 `storage/backups/before-draft-20260906-202016.db`。迁移新增草稿、列、单元格、提案、任务、版本、会话和事件表，不删除旧表。原两轮 7+1 个标签已合并为 8 列；英文原值留在证据中，已知选项标准显示中文，未覆盖词汇标记待确认。同名不同定义不会合并。旧 Reasonix 历史会话没有删除。

恢复操作是显式工具，不自动执行：先在界面暂停任务，再运行 `scripts/stop.ps1` 停止本项目服务，然后：

```powershell
.venv\Scripts\python.exe scripts/restore_database.py storage/backups/before-draft-20260906-202016.db
```

恢复工具先备份当前库，再恢复指定备份；只接受本项目 backups 目录内文件，并拒绝服务仍在运行时恢复。恢复旧库后重新启动新版应用，会重新迁移出草稿。该操作回滚数据库，不自动回滚应用代码。不要手工删除 SQLite WAL 文件或 Reasonix 历史目录。

## 验证与接口

```powershell
.venv\Scripts\python.exe -m pytest -q
```

`scripts/draft_acceptance.py`、`scripts/chat_acceptance.py`、`scripts/benchmark_same_model.py` 是真实模型验收脚本，会消耗已有模型额度，使用独立的 `storage/draft-acceptance`，不写用户正式库。验收结论和限制见 `docs/改造验收.md`。

主要 API：`GET /api/drafts/{id}`、`GET .../sheet?version=...`、`POST .../proposals`、`POST .../proposals/{pid}/confirm`、`PATCH .../cells/{product}/{column}`、`POST .../versions`、`GET .../compare`、`POST .../export`、`GET .../events`；任务使用 `/api/jobs/{id}/stop|resume|cancel`。服务仅监听本机，拒绝跨站写请求。MCP 使用相同草稿业务服务，并将读取工具声明为只读。

Skill 接入新增 `GET .../text-records`、`POST .../text-records/extract`、只读 MCP `read_tagging_rules(topic)`；变更提案增加 `expand`，定义增加 `judgment`，属性列值只接受 true/false/null。核心规则注入数据集 Reasonix 指令，参考按需读取；冻结规则内容直接传给后台模型。验收脚本 `scripts/skill_acceptance.py` 使用每次独立目录；报告见 `docs/Skill接入验收.md`。
