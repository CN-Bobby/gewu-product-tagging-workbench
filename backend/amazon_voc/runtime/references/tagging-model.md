# V4 语义事件与动态标签

## 1 统计单位

一条评论可以拆成多个语义事件。一个事件只表达一个主要的“产品对象或部件 × 属性 × 体验结果”。每个事件保留完整评论、最小充分证据片段、评论 ID、事件 ID 和 ASIN。

避免过拆：同一动作、同一结果的修饰语留在一个事件中；只有产品对象、任务或体验结果独立变化时才拆分。

## 2 人群

人群不是静态身份列表，而是影响任务和成功标准的执行者特征：

- 实际使用者与购买者；
- Buyer/User 关系和各自诉求；
- 明确的生理或物理限制；
- 专业度、熟练度和使用频率；
- 稳定角色约束。

不得根据姓名、照片、常识或刻板印象猜测年龄、职业、收入和生活方式。购买者身份只有在重复改变动机或任务时才进入细分键，否则作为细分内部信息。

案例：评论明确提到儿童无法理解说明书和独立操作，可记录“低龄、弱操作能力”；不能仅因产品标为儿童用品就推断具体年龄或手部力量。

## 3 场景

场景由会改变任务或成功标准的条件组成：

- 地点；
- 环境压力，如温度、速度、湿度、拥挤或时间限制；
- 前置动作、核心动作和后置动作；
- 社交与情绪背景；
- 制度、兼容和安全约束；
- 触发时机。

地点本身不是场景。相同地点下任务或约束不同可以拆分；不同地点下任务和成功标准相同应合并。

## 4 动机与任务

动机回答“为什么现在要做”，任务回答“用户要取得什么进展”。

任务可以包含功能、情感和社交价值，但必须保持解决方案无关。标准 JTBD：

> 【人群】在【场景】中，出于【动机】，要完成【核心任务】，并希望【获得可观察结果】。

明确动机放入 `motivation.explicit`；从行为和结果归纳出的动机放入 `motivation.inferred`，并在 `inference_basis` 中引用事件证据。

## 5 体验、痛点和痒点

- 产品对象：整件产品、部件、材料、包装或履约环节。
- 属性：客观或可比较特征，不使用空泛“质量好/差”代替具体属性。
- 结果：使用后实际发生的状态。
- 痛点：导致失败、风险、损失、阻断、放弃或明显负担。
- 痒点：任务仍可完成，但体验、审美、情感或效率存在改善空间。
- 期望结果：用户明确希望提高或降低的可观察结果。

星级和情感只作背景与统计变量。不得仅凭低星将普通抱怨升级为痛点，也不得仅凭高星将属性升级为 Aha Moment。

## 6 动态标签而非固定标签树

先保留原始表达，再在当前任务内生成语义归一标签。建议使用：

`对象 → 部件 → 属性 → 结果/需求`

它是数据组织方式，不是跨品类固定 L1/L2/L3 字典。每个任务输出动态词典，记录原始表达、标准表达、定义、包含/排除例和支持事件。

案例：“勒出红印”和“袜筒太紧提不上”不能仅因都含“紧”就合并；只有对象、部件、属性和结果一致时，才能归为“袜筒罗纹口弹性不足”。

## 7 类 KANO

评论数据不能正式判定 Kano 基本型、期望型、魅力型。报告可根据频率、正负结果、明确期望和替代行为生成“类 KANO 优先级推断”，但每项必须写依据和置信度。禁止使用跨品类固定关键词表直接分类。
